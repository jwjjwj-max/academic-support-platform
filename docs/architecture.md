# 第一至四周架构与业务决策

## 权限模型

长期账号类型只有：

- `STUDENT`：学生账号；
- `ADMIN`：日常业务管理员；
- `SYSTEM_OWNER`：系统负责人，仅管理管理员账号和系统级事务。

“学业攀登者 / 学业领航者”不是长期账号角色，而是报名表 `application.participant_role` 的期次身份。数据库通过 `(period_id, student_user_id)` 唯一约束保证同一学生同一期只有一个身份，不同期可重新选择。

学生注册后账号可以登录，但 `student_profile.review_status` 未通过时只能查看和修改资料，报名服务后续必须复用此审核门槛。

## 资料与快照

学生身份资料包含姓名、学号、学院、专业和年级。已审核资料发生变更或驳回后重提时，进入 `PENDING`；微信号与选填电话不会单独触发复审。报名提交时写入 `application_profile_snapshot`，因此以后修改账号资料不会覆盖已经通过的报名和正式帮扶对。

## 两类绩点

- `application.cumulative_gpa`：学生报名时自行填写的累计平均绩点，只供报名审核与匹配参考；
- `participant_term_grade.term_gpa`：管理员从每期成绩单的“平均学分绩点”导入；
- `participant_term_grade.term_gpa_rank`：从“平均学分绩点排名”导入，仅管理员可见。
- `participant_term_grade.professional_student_count`：从该次整院成绩表按“年级 + 专业”计数后写入的分母快照，仅管理员可见。

参考成绩单同时存在“平均绩点”和“平均学分绩点”，导入映射不得模糊选择前者。

排名所处范围是同年级、同专业。管理员看到的“专业前百分比”为 `专业内排名 / 专业人数 × 100%`，数值越小越靠前；帮扶前百分比减去帮扶后百分比即排名提升百分点，正数表示提升。人数跟随每次导入固化，后续学生规模变化不会改写历史结果。

## 状态与审计

- 管理员审核驳回、密码重置、账号停用、期次阶段变更必须有原因；
- 期次普通编辑不能改变阶段，阶段通过专用接口按顺序流转；
- 管理员停用、密码重置会增加 `token_version`，令已有 JWT 立即失效；
- 关键操作写入 `operation_log`，资料审核另有版本快照历史。

## 第四周成果数据流

成绩导入采用两步式：每个阶段上传一份整院成绩表，原始文件进入私有目录并生成 `PREVIEWED` 批次，管理员核对学号、年级、专业、平均学分绩点和专业内排名映射后才解析。系统先校验学号唯一性，再按“年级 + 专业”统计全部学生并保存 `grade_cohort_stat`；参与者集合来自本期正式 `support_pair` 双方的报名快照，只有参与者的绩点、排名和对应人数快照写入 `participant_term_grade`。导入完成后批次改为 `IMPORTED`，同一批次不能重复确认。

学生成果查询以当前登录用户 ID 为唯一过滤条件，在服务端按期次聚合帮扶前后绩点；返回结构从设计上不包含排名字段。德育素质分文件不做数值计算，只维护 `DRAFT → PUBLISHED → WITHDRAWN` 发布状态，删除为带操作者和时间的逻辑删除。

## 原型真实化边界

原型的 localStorage、内置人物、角色切换和演示成功提示不进入正式工程。正式前端只展示 API 返回数据。

## 第三周材料状态机

- 照片：`PEER_PENDING`（待同伴确认）→ `ADMIN_PENDING`（待管理员审核）→ `APPROVED`；管理员可改为 `REJECTED`，仅上传人可重提并重新从同伴确认开始。
- 感悟：`SUBMITTED`（提交后管理员可查看）；同一帮扶对每名成员一条当前记录，提交后锁定。历史版本中被驳回的感悟仍可重提，但新提交不再进入管理员审核。
- 帮扶对：`ACTIVE` → `COMPLETED`（人工验收）或 `ENDED`（管理员解除）。材料数量达标不会自动改变帮扶对状态。
- 新增照片在 `TRACKING` 阶段正常收集，`ACCEPTANCE` 阶段允许在最高张数内补交；活动感悟在 `TRACKING` 或 `ACCEPTANCE` 阶段开放；被驳回材料可在两个阶段重提；审核可在 `TRACKING` 和 `ACCEPTANCE` 阶段进行；人工验收仅在 `ACCEPTANCE` 阶段开放。

每次照片提交、同伴确认、审核、驳回、感悟提交和重提同时写入 `pair_material_history` 和关键操作日志。历史期次由同一归属接口只读返回。

## 私有文件边界

照片存储键由 UUID 随机生成，目录不参与前端静态发布。上传同时校验扩展名、声明 MIME、文件签名字节和大小。学生下载照片时后端重新校验其是否为该正式帮扶对成员；管理员按业务权限访问。响应使用 `private, no-store`，不能通过猜测静态路径绕过鉴权。
